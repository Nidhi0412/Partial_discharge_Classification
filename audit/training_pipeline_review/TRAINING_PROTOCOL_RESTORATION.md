## Result and example exports

`code/training_artifacts.py` restores training-history figures, confusion matrices,
ROC plots, classification reports, TensorBoard logs and H5 compatibility exports
alongside the existing histories, metrics, traced prediction CSVs and native
optimizer-containing Keras recovery snapshots.

- `best.keras` and `model.keras`: the primary best-validation-loss model.
- `model.h5`: the same selected model, exported as real HDF5.
- `best_val_accuracy.keras` and `best_weights.h5`: secondary best-validation-
  accuracy checkpoint, matching the old saved-checkpoint criterion. This is
  separately identified and is not used for holdout-based checkpoint selection.
- `augmented_samples/<material>/`: up to five examples per class per fold/final
  fit, with original/augmented PNG, exact float32 NPY, seed, transform parameters,
  source image/recording/group ID and tensor hash. Samples are generated by the
  actual training input pipeline. Prefetched examples are not asserted to be
  consumed optimizer batches; PNGs are quantized previews and NPYs are exact.
  The original VGG iterator additionally saved every generated augmented PNG;
  the restored default deliberately bounds sample exports to five per class,
  not every image of every epoch. This affects archival volume, not augmentation
  applied to the full training membership. It is documented rather than presented
  as an exact reproduction of historical disk output volume.
